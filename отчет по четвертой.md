# Схема преобразования сетевых ошибок в исключения предметной области

## Иерархия исключений

Все исключения наследуются от базового класса `ApiException`:

- **NetworkException** — сеть недоступна, таймаут соединения
- **UnauthorizedException** — HTTP 401, требуется аутентификация
- **ForbiddenException** — HTTP 403, недостаточно прав
- **NotFoundException** — HTTP 404, запись не найдена
- **ConflictException** — HTTP 409, бизнес-правило нарушено
- **ValidationException** — HTTP 400/422, ошибки валидации полей (содержит `Map<String, String> errors`)
- **ServerException** — HTTP 5xx, ошибка сервера

## Таблица преобразований

| HTTP Код | Доменное исключение | Отображение в UI |
|----------|---------------------|------------------|
| 400 | ValidationException | Красный текст под полем формы |
| 401 | UnauthorizedException | Snackbar |
| 403 | ForbiddenException | Snackbar |
| 404 | NotFoundException | Snackbar |
| 409 | ConflictException | Диалоговое окно |
| 422 | ValidationException | Красный текст под полем формы |
| 5xx | ServerException | Snackbar с кнопкой "Повторить" |
| Timeout | NetworkException | Snackbar |
| No connection | NetworkException | Snackbar |

## Поток обработки
HTTP Response (PocketBase)
↓
Dio Interceptor (onResponse)
↓
mapHttpError(status, data)
↓
DioException с полем error: ApiException
↓
guard() в репозитории
↓
Доменное исключение в UI


## Реализация

**Интерсептор преобразует HTTP-коды в ApiException:**

onResponse: (response, handler) {
  if (status >= 400) {
    return handler.reject(
      DioException(
        error: mapHttpError(status, response.data),
      ),
    );
  }
}
Функция mapHttpError() преобразует конкретные коды:

ApiException mapHttpError(int status, dynamic body) {
  if (status == 400 && body is Map && body['data'] is Map) {
    final errors = <String, String>{};
    // Разбор ошибок валидации
    return ValidationException('Ошибка валидации', errors);
  }
  
  return switch (status) {
    404 => NotFoundException(message),
    409 => ConflictException(message),
    >= 500 => ServerException(message),
    _ => ServerException('Неизвестная ошибка'),
  };
}
Функция guard() оборачивает запросы:

Future<T> guard<T>(Future<T> Function() action) async {
  try {
    return await action();
  } on DioException catch (e) {
    if (e.error is ApiException) throw e.error;
    
    throw switch (e.type) {
      DioExceptionType.connectionError => const NetworkException(
        'Не удалось соединиться с сервером',
      ),
      DioExceptionType.connectionTimeout => const NetworkException(
        'Сервер не ответил вовремя',
      ),
      _ => const ServerException(),
    };
  }
}
UI обрабатывает доменные исключения:
try {
  await guestRepo.createAsync(guest);
} on ValidationException catch (e) {
  setState(() => _serverErrors = e.errors);
  _formKey.currentState!.validate();
} on ConflictException catch (e) {
  showDialog(context: context, ...);
} on NetworkException catch (e) {
  ScaffoldMessenger.of(context).showSnackBar(...);
}
## Встреченная ошибка CORS и её устранение
Проявление проблемы
При первом запуске приложения в консоли браузера появилась ошибка:

Access to XMLHttpRequest at 'http://localhost:8090/api/...' 
from origin 'http://localhost:5555' has been blocked by CORS policy
Данные не загружались, списки показывали "Сервер недоступен".

Причина
CORS (Cross-Origin Resource Sharing) — механизм безопасности браузера. Браузер блокирует запросы с одного origin на другой.

Проблема была в несоответствии хостов:

Flutter приложение: http://localhost:5555
PocketBase API: http://127.0.0.1:8090
Браузер считает localhost и 127.0.0.1 разными origin, хотя они указывают на один компьютер.

Решение
Нужно было унифицировать origin для приложения и API.

1. Изменить запуск Flutter с localhost на 127.0.0.1:

flutter run -d chrome --web-hostname 127.0.0.1 --web-port 5555
2. Обновить config.dart:

const apiBaseUrl = String.fromEnvironment(
  'API_BASE_URL',
  defaultValue: 'http://127.0.0.1:8090/api',  // было localhost
);
Проверка
После изменений оба сервиса на одном хосте:

Flutter: http://127.0.0.1:5555
PocketBase: http://127.0.0.1:8090

Status: 200 OK
Access-Control-Allow-Origin: http://127.0.0.1:5555
В консоли видны логи:

[API] GET http://127.0.0.1:8090/api/collections/guests/records?perPage=200&sort=name
[API] ← 200 http://127.0.0.1:8090/api/collections/guests/records?perPage=200&sort=name
[API] GET http://127.0.0.1:8090/api/collections/bookings/records?page=1&perPage=10&expand=roomId%2CguestId&sort=checkIn
[API] ← 200 http://127.0.0.1:8090/api/collections/bookings/records?page=1&perPage=10&expand=roomId%2CguestId&sort=checkIn
Вывод
CORS-ошибка была устранена путём унификации origin приложения и API. PocketBase автоматически добавляет необходимые CORS-заголовки для локальной разработки.
