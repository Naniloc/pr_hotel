# Практическая работа 3: Формы, валидация и связанные сущности

## Описание

Развитие приложения системы управления гостиницей: добавлены формы создания/редактирования с валидацией, реализованы все типы связей между сущностями, настроено сохранение данных между перезагрузками.

## Реализованные сущности

### Room (Номер)
Номер (уникальный), floorId → Floor, roomTypeId → RoomType, вместимость, цена. Связи многие-к-одному с Floor и RoomType.

### Booking (Бронирование)
roomId → Room, guestId → Guest, даты заезда-выезда, статус. Связывает Room и Guest (многие-ко-многим через промежуточную сущность).

### Guest (Гость)
Имя, email (уникальный), телефон. Связь один-к-одному с GuestCard.

### GuestCard (Карточка гостя)
guestId → Guest, паспортные данные (серия, номер, кем выдан, дата). Редактируется в той же форме, что и Guest.

### Floor (Этаж)
Номер этажа, количество комнат. Связь один-ко-многим с Room.

### RoomType (Тип номера)
Название, описание. Связь один-ко-многим с Room.

## Архитектура

К слоям из ПР2 добавлены:

- **core/validators.dart** — переиспользуемые валидаторы (required, email, range, positiveInt)
- **screens/*_form_screen.dart** — формы для всех 5 сущностей (одна на создание/редактирование)
- **repositories/** — добавлены методы isEmailUnique, isRoomNumberUnique, сохранение в localStorage

Все репозитории теперь принимают SharedPreferences и вызывают _persist() после изменений.

## Реализация типов связей

### Многие к одному
**Room → Floor, Room → RoomType, Booking → Room, Booking → Guest**

Реализованы через DropdownButtonFormField, заполняемый из репозитория:

```dart
DropdownButtonFormField<int>(
  value: _floorId,
  items: floorRepo.getAll().map((f) => DropdownMenuItem(
    value: f.id, child: Text('Этаж ${f.number}'),
  )).toList(),
)

Один к одному
Guest ↔ GuestCard

Карточка гостя редактируется в той же форме через вложенные поля. При сохранении Guest автоматически создаётся/обновляется связанная GuestCard.

Многие ко многим
Room ↔ Guest через Booking

Booking — промежуточная сущность, связывающая Room и Guest. Один гость может бронировать несколько номеров, один номер — несколько гостей. Классическая реализация многие-ко-многим через связующую таблицу.

Валидация
Валидаторы вынесены в core/validators.dart:

required — обязательность заполнения
email — формат email
maxLength / minLength — ограничение длины строки
positiveInt — положительное целое число
range — диапазон значений
combine — объединение нескольких валидаторов
Проверки выполняются мгновенно в браузере, ошибки показываются под соответствующим полем.

Проверка уникальности
Email гостя:

dart

if (!guestRepo.isEmailUnique(email, excludeId: widget.id)) {
  return 'Email "$email" уже используется';
}
Номер комнаты:

dart

if (!roomRepo.isRoomNumberUnique(number, excludeId: widget.id)) {
  return 'Номер "$number" уже занят';
}
При редактировании excludeId исключает текущую запись из проверки.

Сохранение данных
Все 6 репозиториев используют SharedPreferences для сохранения в localStorage:

dart

class InMemoryRoomRepository {
  static const _key = 'rooms_v1';
  final SharedPreferences? _prefs;
  
  void _restore() {
    final raw = _prefs?.getString(_key);
    if (raw != null) {
      final list = jsonDecode(raw) as List;
      _rooms.addAll(list.map((e) => Room.fromJson(e)).toList());
    } else {
      _rooms.addAll(_seedRooms);
      _persist();
    }
  }

  Future<void> _persist() async {
    await _prefs?.setString(_key, jsonEncode(_rooms.map((r) => r.toJson()).toList()));
  }
}
Каждый метод изменения данных (create, update, delete) вызывает _persist(). При повреждении данных загружаются seed-данные.

Версионирование
Суффикс _v1 в ключах (rooms_v1, bookings_v1) позволяет обновлять формат без потери совместимости. При изменении структуры модели ключ меняется на _v2, и старые данные не ломают приложение.
