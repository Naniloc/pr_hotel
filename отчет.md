# Практическая работа 2: Списки, поиск, фильтрация и пагинация

## Описание

Приложение системы управления гостиницей на Flutter Web с поддержкой списков, фильтрации, сортировки и пагинации.

## Реализованные сущности

### Room (Номер)
Номер, тип (standard, twin, suite, family, apartment), этаж, вместимость, цена, статус доступности. Поддерживает copyWith и логическое/физическое удаление через deletedAt.

### Booking (Бронирование)
Бронирование номера гостем с датами заезда-выезда, статусом (pending, confirmed, completed, cancelled). Поддерживает copyWith и удаление.

## Архитектура

Приложение разделено на слои:

- **models/** — Room, Booking, RoomQuery, BookingQuery, PageResult<T>
- **repositories/** — интерфейсы и in-memory реализация
- **state/** — RoomListNotifier, BookingListNotifier (управление состоянием)
- **screens/** — HomeScreen, RoomsListScreen, BookingsListScreen
- **widgets/** — AppShell, EntityTable<T>, EntityCard<T>, PaginationBar
- **core/** — breakpoints, formatting, theme, scroll_behavior

## Схема слоёв
Presentation (HomeScreen, RoomsListScreen, BookingsListScreen)
↓
State Management (RoomListNotifier, BookingListNotifier)
↓
Repository (RoomRepository, BookingRepository)
↓
Models (Room, Booking, RoomQuery, BookingQuery)

## Почему EntityTable<T> вынесена в отдельный виджет

Без обобщённого виджета потребовались бы две таблицы (для Room и Booking) с дублированием кода для выделения, сортировки, пагинации.

EntityTable<T> решает это:
- Один виджет работает с любым типом T
- Колонки описываются параметром TableColumnSpec
- Логика выделения и сортировки в одном месте
- Легко добавить новые сущности без копирования кода

## Реализованные требования

1. Две сущности (Room, Booking) с copyWith и репозиториями в памяти (20 + 10 записей)
2. Разделение по слоям (models, repositories, state, screens, widgets)
3. Управление состоянием через Provider (ChangeNotifier, LoadStatus, context.watch/read)
4. Поиск по номеру (Room) и имени гостя (Booking) с задержкой 300ms
5. Фильтрация: для Room по типу, этажу, цене; для Booking по статусу
6. Множественное удаление через checkboxes с подтверждением
7. Логическое и физическое удаление (deletedAt + восстановление)
8. Адаптивная вёрстка: < 600px — drawer + карточки, > 900px — NavigationRail + таблица
9. Пагинация (10, 25, 50 записей на странице; кнопки навигации)
10. Сортировка по щелчку на заголовок (переключение направления, стрелка)
11. EntityTable<T> переиспользуется для Room и Booking
12. Задержка поиска 300ms после окончания ввода (Timer + debounce)

## Состояния экрана

Обработаны четыре состояния: idle, loading (индикатор), success (таблица), error (ошибка). Пустой результат показывает отдельное сообщение.

## Демо-данные

Room: 20 номеров (4 этажа). Booking: 10 бронирований.

## Найденная ошибка в deleteMany

Неправильно: `final i = _bookings.indexWhere((b) => b.id == id && !b[i].isDeleted);`

Проблема: `b[i]` пытается обратиться к объекту как к массиву. В лямбде `b` — это один Booking, не массив.

Правильно: `final i = _bookings.indexWhere((b) => b.id == id && !b.isDeleted);`

Просто проверяем свойство в самом объекте.
